# finder-guard

**解决中文输入法下 macOS 因为访达的快速搜索功能出现输入框的后台程序**

一款专门为中文用户打造的小工具，从此告别访达里那个神出鬼没的「黑框」。

---

## 这个故事要从哪里说起

macOS 26 开始，访达多了一个「快速搜索」功能：只要你在桌面或某个窗口里**没选中任何文件**时按下键盘，访达就会弹出一个搜索输入框，一边打字一边帮你过滤文件名。

这本来是个挺贴心的设计……**直到你用的是中文输入法。**

当你开着简体拼音、在访达里敲下第一个字母时，这个输入框被「顶」了出来，同时中文输入法的候选窗又叠加在上面——在深色模式下，它就变成一个刺眼的**黑色方块**；换成浅色模式，又变成一块白色方块。它挡视线、打断思路，而且——

> **系统设置里根本没有关闭它的开关。**

这个坑几乎每个中文用户都会踩到，网上相关吐槽一抓一大把。而 Apple 始终没有给出解决办法。

**所以，我们自己动手写了一个。**

## 它做了什么

一句话：**在访达想弹出输入框的那一刻，把按键「吃掉」。**

当满足以下三个条件时，程序会在系统键盘层直接吞掉你按下的字母/数字键：

- 访达处于前台
- 焦点不在任何文本框里（搜索框、重命名框、对话框都不算）
- 桌面上没有选中任何文件

访达收不到这个按键，自然就不会触发快速搜索，那个黑框也就**永远不会出现**。

而除此之外的一切操作都原样放行：文本框里正常打字、选中文件后直接打字重命名、所有快捷键、其他应用——都不受影响。

## 特性

- 只拦截「快速搜索」的确切触发条件，不碰其他任何输入
- 判定结果每 ~80ms 缓存一次，性能开销小到可以忽略
- 辅助功能查询带 0.15 秒超时：访达万一卡死，也不会卡住你的键盘
- 自带看门狗：系统若禁用拦截器会自动重新启用
- 崩溃自动重启、权限缺失时自动重试自愈（依托 launchd）
- 日志自动管理：超过 1MB 自动轮转，不占磁盘

## 工作原理

- 使用 `CGEventTap` 做会话级全局键盘拦截
- 通过辅助功能接口判断访达的焦点状态和选中状态
- 以 launchd LaunchAgent 方式开机自启、随系统常驻

## 环境要求

- macOS 26+（macOS 15 上也有效，只是黑框不那么显眼）
- Xcode 命令行工具（`swiftc`，用于编译）
- 需要手动在系统设置里授予两项权限（程序本身不会主动弹窗申请）

## 安装

```bash
git clone https://github.com/ryanlonn555-lab/finder-guard.git
cd finder-guard
./build.sh          # 编译 main.swift 并 ad-hoc 签名
./install.sh        # 安装 launchd 开机自启配置
```

然后到**系统设置**里授予权限：

1. **隐私与安全性 → 输入监控** → 添加 `finder-guard` 二进制
2. **隐私与安全性 → 辅助功能** → 添加同一个 `finder-guard`

守护程序开机自启、随系统常驻、崩溃自动重启。

> 不想编译？到 [Releases 页面](https://github.com/ryanlonn555-lab/finder-guard/releases) 直接下载预编译的 `finder-guard-macos-arm64`（Apple 芯片）。

## 验证是否生效

```bash
tail -f ~/finder-guard/guard.log    # 应看到 "finder-guard running (tap OK)."
```

点一下桌面空白处（不选中任何文件）再打字——以前会弹出黑框，现在什么都不发生；在文本框里打字则完全不受影响。

## 常用命令

```bash
# 查看运行状态与拦截日志
cat ~/finder-guard/guard.log

# 停止（黑框会恢复出现）
launchctl bootout gui/$(id -u)/com.local.finder-guard

# 启动
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.finder-guard.plist

# 重启（改了程序后用它重载）
launchctl kickstart -k gui/$(id -u)/com.local.finder-guard
```

## 卸载

```bash
./uninstall.sh
rm -rf ~/finder-guard
```

## 故障排查

- **黑框又出现了** → `cat ~/finder-guard/guard.log`；如果看到
  `cannot create event tap`，说明权限失效 → 到系统设置把 `finder-guard` 的两项授权各「关闭→再打开」一次。
- **macOS 大版本升级后失效** → 重新授权；若仍无效，说明系统 API 可能变了，日志里会有提示。
- **重新编译过程序？** → 代码签名会变，而系统授权绑定签名 → 需要重新授权（这是 macOS 的安全机制，属正常现象）。

## 已知限制

- 访达的「打字即搜索 / 打首字母跳转文件」功能被禁用，需要搜索时请用 `Command + 空格`（聚焦搜索）。
- 选中文件后直接打字重命名**不受影响**（会放行）；按回车进入重命名也正常。
- 程序**不保存任何字符**（日志只记按键码），**不联网**，不干预其他应用。
